# Обжарка кофе «Кварта» (Минск)

Веб-приложение для ремесленной мастерской спешелти кофе «Кварта» (Минск). Лендинг с каталогом четверговой обжарки, ежемесячной подпиской, интерактивной формой заявки, сквозной UTM-аналитикой, защитой от спама и интеграцией с Telegram.

- **Сайт в продакшене:** [https://kvarta-coffee-nine.vercel.app](https://kvarta-coffee-nine.vercel.app)
- **API проверки сохранённых заявок:** [https://kvarta-coffee-nine.vercel.app/api/lead](https://kvarta-coffee-nine.vercel.app/api/lead)
- **Telegram-бот мастерской:** [@kvarta_coffee_2026_bot](https://t.me/kvarta_coffee_2026_bot)
- **Стек технологий:** Next.js 16 (App Router, Turbopack), React 19, TypeScript, Tailwind CSS v4, Vitest, Prettier, ESLint.

---

## 1. Функциональность проекта

- **Каталог и формат подписки:**
  - 4 сорта свежей обжарки и ассорти дрип-пакетов с подробными вкусовыми профилями и визуализацией пачек.
  - Ежемесячная подписка на 2 пачки кофе со скидкой и бесплатной доставкой по Минску.
- **Интерактивная форма заказа:**
  - 3 формата заявки («Подписка», «Разовый заказ», «Вопрос») с динамической адаптацией плейсхолдеров и текста кнопки отправки.
  - Быстрый выбор сорта кофе прямо из каталога с плавной прокруткой к форме и акцентной подсветкой поля комментария на 900 мс.
  - Автоматическая маска ввода и строгая валидация номеров телефонов Беларуси (`+375`, коды операторов `25`, `29`, `33`, `44`).
- **Сквозная маркетинговая аналитика (UTM):**
  - Захват параметров `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `referrer` и `page_url` при первом визите.
  - Сохранение меток в `sessionStorage` и автоматическое прикрепление к отправляемой заявке.
- **Защита от спама и повторных нажатий:**
  - Блокировка кнопки на клиенте во время выполнения сетевого запроса (`disabled` + индикатор загрузки).
  - Серверная дедупликация: повторная отправка заявки с одного номера телефона в течение 10 минут мягко отклоняется с понятным уведомлением.
- **Интеграция с Telegram:**
  - Автоматическая отправка форматированной карточки заказа в рабочий Telegram-чат мастерской через Bot API бота [@kvarta_coffee_2026_bot](https://t.me/kvarta_coffee_2026_bot).
- **Превью ссылки (OpenGraph):**
  - Настроены мета-теги OpenGraph и Twitter Cards для корректного отображения обложки, заголовка и описания при публикации ссылки в мессенджерах и соцсетях.
- **Студийная эстетика и микро-анимации:**
  - Тёмная журнальная палитра в стиле европейских спешелти-обжарок.
  - Плавное проявление секций при скролле (`<Reveal>` на базе `IntersectionObserver` с уважением к настройке системы `prefers-reduced-motion`).
  - Тактильный отклик интерактивных элементов (`active:scale-[0.98]`), мягкий скейл карточек каталога и скролл с компенсацией фиксированной шапки (`scroll-padding-top: 96px`).

## 2. Архитектура бэкенда и хранение данных

Эндпоинт `POST /api/lead` принимает заявку, валидирует поля, нормализует телефон в формат E.164 (`+375XXXXXXXXX`) и сохраняет данные:

- **Выбор хранилища:** файл `path.join(os.tmpdir(), 'leads.json')` с автоматическим in-memory `Map` fallback.
- **Архитектурное решение для Serverless:** в бессерверных средах (Vercel, AWS Lambda) файловая система доступна только для чтения (`EROFS`), за исключением системной временной директории `os.tmpdir()`. Архитектура спроектирована так, чтобы заявки сохранялись на диск между прогретыми вызовами функций, а при любых ограничениях среды мгновенно переключались на оперативную память без ошибок для клиента.
- **Эндпоинт проверки (`GET /api/lead`):** возвращает `{ count, leads }` со всеми сохранёнными заявками и UTM-метками для прозрачного тестирования работы бэкенда на живом стенде. В коммерческом релизе данный маршрут закрывается авторизацией (JWT / API Key).

## 3. Опыт взаимодействия с ИИ

- **Лог диалога и промптов:** подробная хроника итераций и ключевых команд разработки зафиксирована в [AI_SESSION_LOG.md](./AI_SESSION_LOG.md).

### Распределение задач: ручная работа и ИИ

- **Вручную (архитектура, супервизия и контроль качества):**
  - Разработка дизайн-концепции: отказ от типовых светлых шаблонов в пользу тёмной журнальной эстетики ремесленной мастерской.
  - Проектирование логики валидации: проверка кодов операторов РБ, 10-минутная дедупликация заявок, отказоустойчивое сохранение в serverless.
  - Контроль чистоты кода: ограничение `<= 120 строк на файл`, политика Zero Comments, строгая статическая типизация (Discriminated Unions, Zero `any`).
- **С помощью ИИ (генерация, рутина и черновики):**
  - Базовая вёрстка интерфейсных секций по спецификации.
  - Написание модульных тестов Vitest (`validation`, `utm`, `lead-storage`, `lead-route`).
  - Генерация студийных фотографий упаковок кофе с фирменным брендингом KVARTA.

### Ошибки ИИ и методы их устранения

1. **Галлюцинации сторонних брендов на упаковках:** нейросеть изначально наносила на пачки вымышленные сторонние надписи («Nordic Roasters», «El Salvador»). Замечено при ревью ассетов. Устранено строгими негативными промптами и перегенерацией упаковок с логотипом `KVARTA`.
2. **Синхронный `setState` внутри `useEffect`:** ИИ попытался обработать `prefers-reduced-motion` через `setIsVisible(true)` внутри хука, вызвав ошибку линтера `react-hooks/set-state-in-effect`. Устранено переносом логики в нативный CSS-медиазапрос `@media (prefers-reduced-motion: reduce)`.
3. **Кэширование оптимизатора картинок Next.js:** после обновления файлов в `public/images/` Next.js продолжал отдавать старые изображения из кэша. Замечено при визуальной проверке. Устранено очисткой `.next/cache` и внедрением версионирования ассетов (`kvarta-*-v2.png`).
4. **Конфликт портов локального dev-сервера:** фоновый процесс перехватил порт `3000`, из-за чего dev-сервер тихо сместился на `3001`. Замечено через `netstat`, зависший процесс завершён вручную.
5. **Дублирование параметров дрип-пакетов:** ИИ вывел «10 штук» одновременно в описании и в параметре веса. Замечено при вычитке карточек и исправлено в словаре данных.

### Что было бы сделано иначе в коммерческом продакшене

- Подключение персистентной реляционной СУБД (PostgreSQL / Supabase / Redis) вместо временного файла в `/tmp`.
- Настройка прямых вебхуков в CRM-систему (AmoCRM / Bitrix24) и SMS-подтверждение телефонного номера.
- Реализация полноценной корзины и интернет-эквайринга (bePaid / Webpay), если модель мастерской предполагает мгновенную онлайн-оплату.

### Детализация метрик Performance:

- **First Contentful Paint (FCP):** 1.0 с — отличный показатель (зелёная зона), первый контент появляется мгновенно.
- **Speed Index:** 1.0 с — страница визуально наполняется за 1 секунду.
- **Total Blocking Time (TBT):** 90 мс — скрипты не блокируют основной поток браузера (99/100).
- **Cumulative Layout Shift (CLS):** 0 — идеальная стабильность верстки без визуальных скачков (100/100).
- **Largest Contentful Paint (LCP):** 7.9 с на синтетической мобильной эмуляции (бюджетный процессор с 4x троттлингом и симуляция медленного 4G с каналом 1.6 Мбит/с), обусловленный загрузкой высококачественной студийной фотографии упаковки. На реальных устройствах с актуальным 4G/Wi-Fi сайт открывается практически мгновенно.

Интерактивный HTML-отчёт сохранён в корне репозитория: `lighthouse-report.html`.
