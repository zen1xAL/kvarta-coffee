# Обжарка кофе «Кварта» (Минск) — Тестовое задание

Лендинг для ремесленной мастерской спешелти кофе «Кварта» в Минске с работающей формой заявки, защитой от спама, сквозной UTM-аналитикой и редакционной дизайн-системой.

- **Стек:** Next.js 16 (App Router, Turbopack), React 19, TypeScript, Tailwind CSS v4, Vitest, Prettier, ESLint.
- **Архитектурные правила:** Zero Comments Policy, строгая типизация (без `any`), лимит до 120 строк на файл, 100% покрытие ключевой логики тестами.
- **Живой сайт:** [https://kvarta-coffee-nine.vercel.app](https://kvarta-coffee-nine.vercel.app)
- **Проверка сохраненных заявок:** [https://kvarta-coffee-nine.vercel.app/api/lead](https://kvarta-coffee-nine.vercel.app/api/lead)

## 1. Архитектура бэкенда и хранилище заявок

Эндпоинт `POST /api/lead` принимает заявки от клиентов и сохраняет их в хранилище.

### Выбор хранилища

- **Реализация:** `path.join(os.tmpdir(), 'leads.json')` + автоматический in-memory `Map` fallback.
- **Обоснование:** В serverless-окружениях (Vercel, AWS Lambda, Netlify) корневой диск доступен строго только для чтения (`EROFS`). Директория `os.tmpdir()` доступна на запись и позволяет сохранять файл между вызовами теплой лямбды. Если запись в файловую систему блокируется платформой, сервис бесшовно сохраняет лид в оперативной памяти инстанса без пятисотых ошибок для пользователя.
- **Уведомления в Telegram (плюс из ТЗ):** При указании переменных `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` заявка мгновенно и неблокирующе дублируется в рабочий чат обжарщиков.

### Валидация и защита от спама

1. **Белорусские номера (+375):** Строгая проверка кодов операторов `25`, `29`, `33`, `44` и 7 цифр абонента. Автомаска ввода и понятная подсказка с кодами операторов под полем.
2. **Дедупликация на 10 минут:** Клиент блокирует повторные клики по кнопке отправки, а бэкенд отслеживает временную метку последней заявки с этого номера. Повторная отправка в течение 10 минут возвращает статус `200` с сообщением о том, что заявка уже принята и менеджер скоро свяжется (без создания спам-дублей).
3. **Атрибуция рекламы (UTM):** Клиент перехватывает `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `referrer` и `page_url`, сохраняет их в `sessionStorage` и прикрепляет к заявке. Менеджер точно видит, с какой рекламы и объявления пришел клиент.

### Проверка заявок и UTM-меток (`GET /api/lead`)

Для прозрачной проверки работы бэкенда на задеплоенном сайте доступен эндпоинт:

- **`GET /api/lead`** — возвращает `{ count, leads }` со всеми сохраненными заявками и захваченными UTM-метками.
- **Ссылка для проверки:** [https://kvarta-coffee-nine.vercel.app/api/lead](https://kvarta-coffee-nine.vercel.app/api/lead)

> **Примечание по безопасности:** В тестовом задании эндпоинт сделан открытым для проверки ревьюером. В промышленном продакшене доступ к чтению персональных данных закрывается авторизацией (JWT / Basic Auth / API Key).

## 2. Реализованные бонусы из ТЗ («Будет плюсом»)

1. **Дублирование заявок в Telegram:** реализована интеграция с Telegram Bot API (`src/app/api/lead/route.ts`).
2. **Превью ссылки в мессенджерах (OpenGraph):** настроены мета-теги `og:image`, `og:title`, `og:description` и Twitter Cards для красивого отображения карточки сайта в Telegram и соцсетях.

   - Компонент плавного скролл-проявления `<Reveal>` на нативном `IntersectionObserver` с поддержкой `prefers-reduced-motion`.
   - Журнальный зум изображений при наведении (`group-hover:scale-[1.03]`).
   - Тактильный отклик кнопок при клике (`active:scale-[0.98]`).
   - Плавная подсветка поля комментария при автозаполнении сорта из каталога.
   - Универсальный smooth scroll к секциям с компенсацией высоты липкой шапки (`scroll-padding-top: 96px`).

## 3. Раздел для проверяющего (Опыт работы с ИИ)

### Что делали сами, а что ИИ

  - Определение дизайн-системы: отказ от типовых шаблонных карточек в пользу темной журнальной эстетики ремесленной мастерской.
  - Проектирование требований к бэкенду: алгоритм валидации номеров Беларуси, 10-минутная дедупликация, отказоустойчивое хранение в serverless.
  - Контроль чистоты кода: введение лимита `<= 120 строк на файл`, политики Zero Comments и строгой типизации (Discriminated Unions, Zero `any`).
- **ИИ (генерация, рутина и ассеты):**
  - Черновая верстка интерфейсных блоков по спецификации.
  - Написание юнит-тестов для Vitest (`validation`, `utm`, `lead-storage`, `lead-route`).
  - Генерация предметных студийных фотографий упаковок и коробок кофе.

### Где ИИ ошибся и как это заметили

1. **Галлюцинации текста на сгенерированных изображениях:** В первых итерациях генератор изображений наносил на пачки надписи сторонних брендов («Assembly London», «El Salvador»). Заметили при инспекции сгенерированных ассетов. Ошибку устранили строгими промптами с явным указанием бренда `KVARTA` и регенерацией всех 4 позиций каталога.
2. **Синхронный `setState` внутри `useEffect`:** ИИ попытался обработать `prefers-reduced-motion` через вызов `setIsVisible(true)` прямо в теле `useEffect`, что вызвало ошибку линтера `react-hooks/set-state-in-effect`. Ошибку устранили переносом логики в нативный CSS `@media (prefers-reduced-motion: reduce)`.
3. **Кэширование Next.js Image Optimizer:** При перезаписи файлов в `public/images/` Next.js и браузер продолжали отдавать закэшированные версии старых изображений. Заметили отсутствие визуальных изменений на экране. Устранили проблему очисткой `.next/cache` и внедрением версионированных имен файлов (`kvarta-*-v2.png`).
4. **Зависший процесс на порту 3000:** Старый фоновый процесс `next start` перехватил порт `3000`, из-за чего dev-сервер запустился на `3001`, а браузер открывал устаревший билд. Обнаружили через сетевую диагностику `netstat`, процесс завершили.
5. **Дублирование параметров в каталоге:** ИИ поместил «10 штук» одновременно в дескрипторы и в поле фасовки дрип-пакетов. Заметили при проверке карточек и исправили в словаре данных.

### Что не успели или сделали бы иначе

- В продакшене для долговременного хранения заявок подключили бы персистентную базу (PostgreSQL / Supabase / Redis) вместо `/tmp`, настроили автоматические вебхуки в CRM (AmoCRM / Bitrix24) и SMS-верификацию номера.
- Реализовали бы динамическую корзину и онлайн-эквайринг (bePaid / Webpay), если бы бизнес-модель мастерской предполагала моментальную оплату картой онлайн.
